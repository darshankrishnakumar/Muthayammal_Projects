# Apple Health Intelligence AI — System Architecture & Training Guide

## 1. Executive Summary & Audit Findings

The initial audit of `apple_cnn_model_v2.pth` and `apple_cnn_engine.py` revealed that the legacy model suffered from two fundamental limitations:
1. **Task Incompatibility:** A single 5-class classifier combined foliar pathologies (*Cedar Apple Rust*, *Apple Scab*, *Frog-Eye spots*) with whole-fruit decay (*Black Rot* fruit decay).
2. **Calibration Overfitting:** Checkpoint weights were generated by `_calibrate_quick()` on only 8 prototype images in `sample_images/`. The convolutional feature extractors had never seen diverse real-world lighting, grocery varieties, surface bruises, or background occlusions, leading to erratic predictions on real-world apples.

---

## 2. Multi-Model Architecture

The system now decouples pomological (fruit) and foliar (leaf) diagnostics into three dedicated models:

```

```

### Model Specifications
- **Model A (`apple_fruit_condition_v1.pth`):**
  - Architecture: MobileNetV2 with custom 2-stage classification head.
  - Classes: `['Fresh', 'Rotten']`.
  - Application: Classifies whole apple fruit as fresh or rotten/decayed.
- **Model B (`apple_leaf_disease_v1.pth`):**
  - Architecture: MobileNetV2 with fine-tuned inverted residual blocks.
  - Classes: `['Apple_Scab', 'Black_Rot', 'Cedar_Apple_Rust', 'Healthy']`.
  - Application: Diagnoses specific foliar leaf pathogens.
- **Model C (`apple_input_validator_v1.pth`):**
  - Architecture: MobileNetV2 3-way input classifier.
  - Classes: `['apple_fruit', 'apple_leaf', 'unsupported']`.
  - Application: Prevents leaf disease classifiers from evaluating fruit rot and rejects out-of-domain noise.
- **Legacy Fallback (`apple_cnn_model_v2.pth`):**
  - The original 4-Conv Custom CNN is preserved for rollback safety.

## 3. Dataset Management & Instructions

### External Dataset Sources Supported:
1. **Fruit and Vegetable Disease (Fresh vs. Rotten):**
   - URL: [https://www.kaggle.com/dsv/8463025](https://www.kaggle.com/dsv/8463025)
   - CLI: `kaggle datasets download -d sriramr/fruits-fresh-and-rotten-for-classification`
   - Target placement: `datasets/raw/fruit_and_vegetable_disease/`
2. **PlantVillage Apple Leaf Dataset:**
   - URL: [https://figshare.com/articles/dataset/PlantVillage_Dataset/26096800](https://figshare.com/articles/dataset/PlantVillage_Dataset/26096800)
   - Target placement: `datasets/raw/plantvillage_apple_leaf/`
3. **Fruits-360:**
   - URL: [https://www.kaggle.com/moltean/fruits](https://www.kaggle.com/moltean/fruits)
   - Supplementary fruit recognition placement: `datasets/raw/fruits_360/`

### Dataset Preparation:
Run the preparation script to verify file integrity, deduplicate via MD5 hashing, and generate stratified splits:
```bash
python scripts/prepare_datasets.py --raw_dir datasets/raw --processed_dir datasets/processed
```

## 4. Reproducible Training Pipeline

Train individual task models with two-stage transfer learning (head warm-up followed by selective backbone fine-tuning):

```bash
# 1. Train Fruit Condition Classifier
python scripts/train_fruit_condition.py --data_dir datasets/processed/fruit_condition --epochs_head 5 --epochs_fine 5

# 2. Train Leaf Disease Classifier
python scripts/train_leaf_disease.py --data_dir datasets/processed/leaf_disease --epochs_head 5 --epochs_fine 5

# 3. Train Input Validator
python scripts/train_input_validator.py --data_dir datasets/processed/input_validator --epochs_head 5 --epochs_fine 5
```

---

## 5. Model Evaluation & Performance

Run the evaluation engine against held-out test datasets:
```bash
python scripts/evaluate_models.py --checkpoint models/apple_fruit_condition_v1.pth --test_dir datasets/processed/fruit_condition/test
python scripts/evaluate_models.py --checkpoint models/apple_leaf_disease_v1.pth --test_dir datasets/processed/leaf_disease/test
```
Evaluation metrics, per-class breakdown, and confusion matrices are saved to `evaluations/`.
